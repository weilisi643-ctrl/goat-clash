# 04 牧场界面列出省份：风险评估（2026-10-28）

> 结论先行：**可以列，整体风险中等，但前提是严格按本文的"安全写法"做**。如果做不到"34 个全称一个不漏、台湾和港澳归属正确、不配地图"，就别列省份，维持 00 号文档"只显示牧场名"的方案（低风险）。
> 风险等级：🔴高 / 🟡中 / 🟢低。"⚠待核实"表示我没找到直接针对小游戏的官方条文，是按通用规范推断的。

## 1. 可能触及的问题

| # | 问题 | 风险（不处理 → 按本文处理） | 依据 |
|---|---|---|---|
| 1 | **漏列省级行政区**，尤其漏掉台湾省，或者漏掉港澳 | 🔴 → 🟢 | 民政部统计口径：全国 34 个省级行政区划（4 个直辖市、23 个省、5 个自治区、2 个特别行政区），含"台湾省"。[民政部行政区划统计表](http://xzqh.mca.gov.cn/statistics/2022.html)；[民政部 2025 年发布会](https://m.thepaper.cn/newsDetail_forward_31123516)。一份"全国省份清单"如果漏了台湾，会被理解为领土表述不完整 |
| 2 | **港澳台被并列成"国家"，或单独归入"海外 / 远方"组** | 🔴 → 🟢 | "在任何文字、地图、图表中都要避免让人误以为香港、澳门是国家"；台湾不得与国家并列；"台湾与港澳并列时应称港澳台地区"；不用"两岸三地"。[新华社禁用词（港澳台类）](https://gd.huaxia.com/c/2024/06/25/1934808.shtml)、[关于正确使用涉台宣传用语的意见](https://zh.wikisource.org/wiki/%E5%85%B3%E4%BA%8E%E6%AD%A3%E7%A1%AE%E4%BD%BF%E7%94%A8%E6%B6%89%E5%8F%B0%E5%AE%A3%E4%BC%A0%E7%94%A8%E8%AF%AD%E7%9A%84%E6%84%8F%E8%A7%81)。所以**现在的"远方牧场"一旦和省份清单同屏出现，就会产生歧义**（容易被理解成"境外区"），必须改 |
| 3 | 台湾的称呼 | 🟡 → 🟢 | 同上：《涉台用语意见》写明"台湾是中国一个省……现在一般不称台湾省，多用台湾地区或台湾"。但在"省级行政区全称清单"这种语境下，民政部统计表用的是"台湾省"。⚠待核实：游戏里用哪个更稳妥。建议清单用民政部口径"台湾省"，因为和其他 33 个全称格式一致，不会显得被特殊对待 |
| 4 | **配地图或轮廓图**（哪怕是简笔示意、分区色块） | 🔴 → 🟢（不配） | 公开登载地图要送审并标注审图号；跨两个以上省份的地图由自然资源部审核；改色、裁切也要重新送审。[地图审核管理规定](https://www.gov.cn/zhengce/2019-08/13/content_5711407.htm)、[地图管理条例](https://www.gov.cn/zhengce/zhengceku/2015-12/14/content_10403.htm)、[两部门 2024 通知](https://www.gov.cn/zhengce/zhengceku/202405/content_6950568.htm)、[中国测绘学会答疑](https://www.csgpc.org/detail/24825.html) |
| 5 | 名称不规范：只写简称（如"内蒙""广西"），或民族自治区不写全称 | 🟡 → 🟢 | 统一用民政部全称（如"广西壮族自治区""新疆维吾尔自治区"）。⚠ 名称不规范在游戏审核里是否会直接导致驳回，我没查到明文；但用全称可以消除这个隐患 |
| 6 | **地域歧视、对立文案**：省份并排展示 + 排行，容易被做成"某省碾压某省" | 🟡 | 微信小游戏审核驳回项包括有害信息；题库要避开"宗教民族""领土地图"（[微信审核常见驳回](https://developers.weixin.qq.com/minigame/product/reject.html)，清单第 42–43 行）。省份名一出现，玩家评论和截图传播的风险就比大区名更高。按 00 号文档执行：比人均分、文案中性、不做省对省海报 |
| 7 | 大区划分本身（"某省归哪个大区"）引起争议 | 🟡 | 七大地理分区是习惯性的地理划分，不是法定行政区划，各种资料的分法略有出入（如内蒙古、陕西）。⚠待核实：没有找到唯一的官方分区表。需要加一行说明"按常见地理分区，仅用于游戏分组"，并允许玩家自选牧场，不和省份绑定 |
| 8 | 版号 / 出版内容审核 | 🟡 | 如果日后申请版号，游戏内全部文字都要过出版内容审核，涉及领土和行政区划的表述会被重点看（⚠ 按出版物通用规范推断，没找到针对游戏的单独条文）。按本文写法做，应该不构成障碍 |
| 9 | 隐私：列了省份，玩家可能以为游戏会定位自己 | 🟢 | 仍然由玩家自选，不读 IP，不读 getUserInfo 里的 province（见 00 号文档） |

**整体：** 按第 3 节写法做，整体 🟡中偏低；不按这个写法做，有一项触发就是 🔴。相比只显示牧场名（🟢），列省份**多出的风险集中在第 1、2、7 项**，而带来的收益只是"让玩家知道该选哪个"。

## 2. 最安全写法

### 2.1 规则
1. **34 个全部列出**，一个不漏，用全称，排序采用民政部统计表顺序（行政区划代码序）。
2. 台湾省、香港特别行政区、澳门特别行政区**和其他省级行政区同等对待**，放进各自地理上所属的大区。**不单独成组，不另标颜色或星号，不加注释**（不复制民政部表里"*资料暂缺"的标注）。
3. **取消"远方牧场"**（或者至少不和省份清单同屏出现）。不想选或者人在国外的玩家，状态就是"暂未加入牧场"（faction=null），照样能玩。如果确实要保留一个兜底阵营，名字要明显是游戏设定（如"流浪小羊团"），并且**不出现"海外、境外、国外"等字样**。⚠待核实：兜底阵营是否还会被理解为"境外组"，所以最稳妥的是不设。
4. 不配地图、轮廓、剪影，也不画各省形状的旗帜；旗帜只用山羊图案加大区名。
5. 不写评价性文案：不给省份配特产梗、性格标签、方言，不写"最强省"。省份名只出现在"本牧场包含：……"这一行小字里。
6. 页脚说明："分组按常见地理分区，仅用于游戏内组队，不代表任何行政或其他含义。"
7. 排行榜只排**牧场**，**不排省份**，玩家资料里也不显示省份（不选省份，只选牧场）。

### 2.2 34 个省级行政区全称及分组建议
来源：[民政部行政区划统计表](http://xzqh.mca.gov.cn/statistics/2022.html)。分组按常见的七大地理分区（⚠ 非法定，见第 1 节第 7 项）。

| 牧场 | 包含 |
|---|---|
| 华北牧场 | 北京市、天津市、河北省、山西省、内蒙古自治区 |
| 东北牧场 | 辽宁省、吉林省、黑龙江省 |
| 华东牧场 | 上海市、江苏省、浙江省、安徽省、福建省、江西省、山东省、台湾省 |
| 华中牧场 | 河南省、湖北省、湖南省 |
| 华南牧场 | 广东省、广西壮族自治区、海南省、香港特别行政区、澳门特别行政区 |
| 西南牧场 | 重庆市、四川省、贵州省、云南省、西藏自治区 |
| 西北牧场 | 陕西省、甘肃省、青海省、宁夏回族自治区、新疆维吾尔自治区 |

核对：5+3+8+3+5+5+5 = 34 ✔（4 个直辖市、23 个省、5 个自治区、2 个特别行政区都齐了）。

## 3. 对 data/factions.json 的建议改动（只是建议，我没改文件）
```jsonc
{
  "version": 2,
  "provinceSource": "民政部行政区划统计表",   // 新增：名称出处，方便日后核对
  "showProvinces": true,                       // 新增：开关；出问题可以远程一键关闭，只显示牧场名
  "provinceNote": "分组按常见地理分区，仅用于游戏内组队，不代表任何行政或其他含义。",
  "allowNoFaction": true,                      // 新增：允许"暂未加入牧场"
  "factions": [
    { "id": "north", "name": "华北牧场", "flag": "flag_north",
      "provinces": [ {"code":"110000","name":"北京市"}, {"code":"120000","name":"天津市"},
                     {"code":"130000","name":"河北省"}, {"code":"140000","name":"山西省"},
                     {"code":"150000","name":"内蒙古自治区"} ] },
    { "id": "east", "name": "华东牧场", "flag": "flag_east",
      "provinces": [ "…", {"code":"710000","name":"台湾省"} ] },
    { "id": "south", "name": "华南牧场", "flag": "flag_south",
      "provinces": [ "…", {"code":"810000","name":"香港特别行政区"}, {"code":"820000","name":"澳门特别行政区"} ] }
    // 其余大区同上；provinces 只用于展示，不参与积分逻辑
  ]
  // 删除 id 为 "faraway" 的"远方牧场"；progress 中 faction 为 null 即"暂未加入"

```
- `code` 用 6 位行政区划代码（方便排序、和官方核对）。⚠ 台湾 710000、香港 810000、澳门 820000 是国家标准 GB/T 2260 中的通行代码，请程序接入前对照民政部最新发布的代码再核实一次。
- 程序加一个自检：启动时断言 `provinces` 总数 === 34 且没有重复，不通过就自动 `showProvinces=false`，防止改数据时漏项上线。
- 已存量玩家如果 faction 为 "faraway"，迁移时改为 null，并提示重新选择（第一期还没上线的话可以忽略）。

## 4. 明确建议
1. **第一期上线先不列省份**（`showProvinces=false`），只显示牧场名，以最低风险先过审。
2. 数据结构现在就按第 3 节改好（加上 provinces，删掉"远方牧场"），过审稳定后再远程打开 `showProvinces`。如果主人坚持第一期就列，必须同时满足第 2.1 节全部 7 条，特别是：34 个全称不漏、台湾和港澳在各自大区里同等列出、没有"远方"或"海外"组、零地图。
3. 无论列不列，排行都只到牧场一级，绝不做省份排行。
